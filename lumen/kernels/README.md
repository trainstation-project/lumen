# `lumen/kernels`

The op layer: the dispatcher, the kernels of every graph primitive, and the
reference interpreter. Two kinds of code live here:

* **Tensor ops** (`fill_`, `copy_h2d`/`copy_d2h`, `wait`, `dummy_op`): each a
  static [`Op<K>`](mod.rs) dispatched on a tensor's device, modeled on
  PyTorch's `c10::Dispatcher`.
* **Graph-primitive kernels**: one folder per primitive family, each with an
  `mps/` subfolder holding Metal kernels (`kernels.metal`) and their host
  side (`mod.rs`, an `encode` function). These are not `Op`s: a compiled
  `Plan` (`graph_compiler/plan.rs`) runs each step on MPS through
  [`mps::encode`](mps/mod.rs), which routes on the step's `Primitive`, and
  on a TPU through [`tpu::encode`](tpu/mod.rs) (kernels in lumen's Pallas); on any
  other executor the plan evaluates the step with
  [`reference::eval_raw`](reference.rs).

Fused kernels generated by `graph_compiler/mps` and `codegen/mps` reuse the
templates in these `.metal` files (compiled with `TEMPLATES_ONLY`, see
[`mps/README.md`](mps/README.md)).

## Files

| File | Contents |
| --- | --- |
| `mod.rs` | `DispatchKey`, `Op<K>` (static + dynamic registries, `register`/`unregister`/`kernel`/`dispatch`), `vector_size` for Python kernels, and the module list. |
| `reference.rs` | The reference interpreter: `run(graph, inputs)` evaluates a whole `Graph` in `i128`/`f64` values rounded to each dtype; `eval_raw` evaluates one primitive on raw host buffers (a plan's non-MPS steps); `philox_bits`/`philox4x32` for `RandomBits`. |
| `python.rs` | Python bindings (`python` feature): `_register_kernel`, `_unregister_kernel`, `_registered_ops`, `_dummy_op`; the Python-kernel table (`KernelHandle`) and launcher cache. |
| `tvm_ffi.rs` | Calls a TVM-FFI function through its C ABI, loading `libtvm_ffi` at run time: how a CuTe DSL kernel compiled with `--enable-tvm-ffi` launches without Python. |
| `dummy_op.rs` | `lumen::dummy_op`, an op with no built-in kernels, for testing Python kernel registration. |
| `__init__.py` | The `lumen.kernels` package: `register`, `unregister`, `registered_ops`, `signature`; imports `lumen.kernels.fill.cuda` when CUDA is available. |
| `_C.pyi` | Type stub for what `python.rs` defines. |
| `tests.rs` | Dispatcher tests (static-before-dynamic, per-op dynamic kernels, the missing-kernel panic), `fill_layout`, `vector_size`. |

## Dispatch per device

**Tensor ops.** An op is a `static FOO: Op<FooKernel> = Op::new(op_name!("foo"), builtin)`,
where `builtin` is a `match` on `DispatchKey` (`Cpu`, `Cuda`, `Mps`, `Meta`)
returning `Option<FooKernel>`; arms are `#[cfg(lumen_mps_linked)]` /
`#[cfg(lumen_cuda_linked)]` gated. `Op::kernel(key)` tries the built-in, then
the process-wide dynamic registry (`Op::register`, PyTorch's
`TORCH_LIBRARY_IMPL`). `register` refuses a key that has a built-in kernel,
since it would never be used. `dispatch(device)` panics with
`"<op> has no kernel for <key> (<device>)"` if neither has one.

**Python kernels** (`python.rs`). Only ops listed in `OP_SIGNATURES`
(`dummy_op`) accept them, and never for the CPU. A registered
callable is a *compile hook*: `(dtype, shape, strides, vector_size) ->
launch(address, value, stream)`. Each op keeps a parallel `Op<KernelHandle>`
(`DUMMY_OP_PY`); the op's entry function (e.g. `dummy_op`) checks
`python::handle_for` first and falls back to `dispatch`. Launchers are
cached per (kernel, dtype, shape, strides, vector size) and, if they expose
`__chandle__`, called through `tvm_ffi.rs` instead of Python.

**Plan steps.** A `Plan` step on MPS goes to `kernels::mps::encode`, which
picks the family's `encode` by `Primitive`; reductions, `cumsum`,
`linear_cross_entropy` and `Fusion` get a scratch pointer too. On a TPU,
`kernels::tpu::encode` does the same (only `dot_general` so far). Elsewhere the
plan calls `reference::eval_raw` for every step.

## The reference interpreter

`reference.rs` is the semantic ground truth: integer values are held as
`i128` and wrapped to their dtype, floats as `f64` rounded to their dtype
after each primitive (`round`, `saturate` for float-to-int casts). It
supports multi-output `Fusion` bodies (evaluating the body recursively) and
`FusionOutput`. Compiler tests (`graph_compiler/tests.rs`,
`plan_tests.rs`) compare plans and rewrites against `reference::run`.

## Invariants & gotchas

* MPS kernels take 32-bit thread positions: `mps::encode` rejects a step
  whose output has more than `u32::MAX` elements.
* The dynamic registry is global; tests that register kernels must each use
  an op of their own (see `tests.rs`).
* `Concatenate` has no standalone MPS kernel: it must be fused.
  `ToHost`/`ToDevice` and `CustomCall` never reach `mps::encode`.
* Adding a primitive means a `reference.rs` arm, an arm in `mps::encode`
  (and `scratch_bytes` if it needs scratch), and, for a new `kernels.metal`,
  an entry in `PRIMITIVE_KERNELS` in `build.rs`.
